# Tambala WhatsApp via ZapClaw

## Webhook

Configure ZapClaw's native webhook destination as:

`https://tambala-mcp.onrender.com/webhooks/zapclaw/whatsapp`

Subscribe to `message.received`. The MCP verifies `X-ZapClaw-Signature` before processing a message.

## Render environment variables

Add these server-side variables:

- `ZAPCLAW_API_KEY` — API key generated in ZapClaw.
- `ZAPCLAW_WEBHOOK_SECRET` — signing secret generated by ZapClaw's Webhook settings.
- `ZAPCLAW_FROM` — the connected WhatsApp Business number in E.164 form; the adapter normalizes it to digits for the ZapClaw send API.
- `ZAPCLAW_BASE_URL` — optional; defaults to `https://api.zapclaw.app`.

The existing MCP Supabase variables remain the source of database access. The WhatsApp adapter does not create a second database.

## Flow

WhatsApp -> ZapClaw -> `/webhooks/zapclaw/whatsapp` -> Supabase persistence/deduplication -> Tambala orchestrator -> ZapClaw send API -> WhatsApp.

Inbound `message_id` is the database primary key so webhook retries/redeliveries cannot create duplicate inbound records.

## Database migration

Apply:

`docs/migrations/20261025_whatsapp_zapclaw.sql`

This creates `public.whatsapp_inbound_messages` in the same Supabase project already used by Tambala MCP.

## Important

ZapClaw webhook configuration is done in the ZapClaw dashboard. The webhook URL must be public HTTPS. ZapClaw signs webhook requests with HMAC-SHA256 and expects a 2xx response after successful handling. The send API uses `POST /api/v1/send/text` with `X-API-Key` authentication.
